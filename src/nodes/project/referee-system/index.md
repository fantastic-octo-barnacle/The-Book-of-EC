# 裁判系统通信

## 项目目的

使用 RoboMaster Type C 开发板接收实际裁判系统数据，从连续 UART 字节流中恢复协议帧、校验数据并维护有类型的最新状态。项目用于练习 Embassy UART、流式协议解析、CRC、错误恢复和业务状态建模。

## 完成判据

- **核心目标**形成最小可运行结果，可用于检查当前进展；
- **标准目标**是完成本节点的判据；
- 本项目不设置挑战目标。

应先得到完整的核心结果，再进入标准目标。不得以大量未完成的高级功能替代较低层的完整结果。

## 提供资源

- RoboMaster Type C 开发板，MCU 为 STM32F407IGH6；
- 实际可用的裁判系统设备；
- 连接、供电和调试所需器材；
- 经过检查的最小 Type C 工程脚手架。

脚手架只包含 Cargo 项目、编译目标、链接配置和 probe-rs 基本配置，不包含日志、GPIO、UART、CRC 或协议解析。标准实现使用 Rust 与 Embassy。协议资料、数据手册、接线方式和串口参数由实现者自行查找并核对。不额外提供录制数据或协议模拟器。

## 核心目标

- 自行完成时钟、日志、GPIO 和 UART 初始化；
- 从 UART 连续接收裁判系统字节流；
- 不假设一次 UART 读取恰好对应一个完整协议帧；
- 搜索帧头，并根据协议长度字段收集一帧数据；
- 完成协议要求的 CRC8 与 CRC16 校验；
- 解析导师指定的一类数据帧，并保存为字段含义明确的 Rust 类型；
- 在收到坏帧、无关字节或不完整数据后继续寻找后续合法帧。

允许合理使用第三方依赖完成 CRC，但实现者应能解释依赖的用途和选择依据。不得使用已经完整实现该裁判系统协议、从而替代流式解析核心工作的依赖。

## 标准目标

- 至少解析导师根据实际协议版本指定的三类数据帧；
- 使用结构体和枚举表达不同命令及其数据，避免在业务代码中反复操作无含义的字节偏移；
- 维护所解析数据的最新状态，并区分尚未收到与已经收到的字段；
- 根据一个指定业务字段控制 LED、蜂鸣器或其他简单输出；
- 正确处理未知命令、非法长度、CRC 错误、帧截断和帧间垃圾字节；
- 为不依赖 UART 的纯协议解析逻辑编写单元测试，覆盖合法帧、CRC 错误、截断帧和垃圾字节后的恢复。

测试数据由实现者根据实际协议构造或从设备通信中取得，任务不提供固定字节流。

## 实现边界

- 不要求支持当前协议版本的所有命令；
- 不要求 GUI、上位机或数据持久化；
- 不要求发送学生机器人交互数据；
- 解析器应适用于分段到达的连续数据，不能只对完整字节数组做一次性解析。
