# 第一阶段：同步探测

## 实现要求

- 创建 Cargo 二进制包，并在 `Cargo.toml` 中明确登记名为 `url-probe-sync` 的 bin。
- 在代码中定义少量固定 URL，按列表顺序逐个发送 GET 请求。前一个目标完成后才能开始下一个目标。
- 使用 reqwest 的阻塞接口，并复用同一个 HTTP client。
- 设置固定请求超时；不读取响应正文。
- 对每个 URL 输出最终状态或简短错误，以及该次请求耗时。
- 输出成功数、失败数和从整批开始到全部结束的总耗时。
- 单个目标失败后继续探测后续目标。目标失败属于正常结果；只有整批任务无法开始或无法完成汇总时，程序才以失败结束。
- 为不依赖网络的逻辑编写单元测试，至少覆盖成功判定和汇总计数。

计时口径必须与[项目总览](./index)一致。同步版的总耗时通常接近各项耗时之和，但不得把这一近似关系写成恒等式。

## 交付要求

GitHub 仓库至少包含：

- 可构建的源码；
- `Cargo.toml` 和 `Cargo.lock`；
- 适用于 Rust 项目的 `.gitignore`，且不提交 `target/`、编辑器状态或本地环境文件；
- 可读的 Git 提交历史；
- README，说明项目行为、正式验收集、超时值、依赖用途、构建与运行方式，并记录一次同步探测结果。

提交前应确认代码已经格式化、Clippy 无警告、测试通过且构建成功。随后运行：

```sh
cargo build
cargo run
```

输出满足要求后，在该提交上创建并推送 `stage-1-sync` tag。tag 必须指向仅包含完整同步版且已通过本阶段验收的提交。

Issue、PR、CI 和覆盖率不属于交付要求。
