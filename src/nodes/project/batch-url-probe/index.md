# 批量 URL 探测器

## 项目目的

用 Rust 分别实现同步和异步 HTTP 探测程序，在相同任务下观察顺序等待与异步并发的行为差异。项目只保留必要的请求、计时、汇总和错误处理逻辑。

默认读者具备基础终端和 Git 使用经验；不要求预先学过 Rust、Cargo 或异步编程。

## 两个阶段

| 阶段     | 产物                            | 主要目的                                                     |
| -------- | ------------------------------- | ------------------------------------------------------------ |
| 第一阶段 | `url-probe-sync`                | 熟悉 Cargo、Rust 错误处理、阻塞 HTTP 请求和基本测试          |
| 第二阶段 | `url-probe-async`，并保留同步版 | 学习 `async`、`.await`、异步运行时和有界并发，并比较两个版本 |

两个阶段在同一个 GitHub 仓库和 Cargo 包中完成。第一阶段验收通过后打 `stage-1-sync` tag；第二阶段验收通过后打 `stage-2-async` tag。最终仓库必须能分别构建和运行两个 bin。

## 统一行为

- URL 列表写在代码中，不接收命令行输入；两个版本使用相同列表。
- 使用 GET 请求，以最终响应状态为准：`2xx` 是成功，非 `2xx`、无效 URL、连接错误和超时是失败。
- 不读取或分析响应正文。单项耗时从实际开始请求计算到取得响应状态或错误。
- 每个 URL 输出探测结果和耗时；全部结束后输出成功数、失败数和整批总耗时。
- 单个 URL 失败是探测结果，不得阻止其他目标继续执行，也不应使已经完整汇总的程序以失败结束。
- 同一固定超时必须用于两个版本，并在 README 中说明。

固定 URL 集合应保持较小，但必须覆盖正常响应、非 `2xx`、无效或无法连接、延迟响应和超时。两个阶段均使用下方集合完成正式验收，不得增加请求次数进行压力测试。

## 正式验收集

固定请求超时为 5 秒，异步版并发上限为 3：

```rust
const URLS: &[&str] = &[
    "https://httpbin.org/delay/10?case=timeout",
    "https://httpbin.org/delay/1?case=slow-1",
    "https://httpbin.org/delay/1?case=slow-2",
    "https://httpbin.org/delay/1?case=slow-3",
    "https://httpbin.org/status/204",
    "https://httpbin.org/status/404",
    "not-a-url",
    "http://127.0.0.1:0/",
];
```

预期结果：

| 目标            | 预期结果                      |
| --------------- | ----------------------------- |
| `/delay/10`     | 在 5 秒处超时，失败           |
| 三个 `/delay/1` | 延迟约 1 秒后返回 `2xx`，成功 |
| `/status/204`   | 立即返回 `2xx`，成功          |
| `/status/404`   | 返回非 `2xx`，失败            |
| `not-a-url`     | URL 解析失败                  |
| `127.0.0.1:0`   | 本机连接失败                  |

两个版本均应汇总为 4 个成功、4 个失败。验收前先确认当前网络可以直接访问 `httpbin.org`；若服务不可用、被代理改写或三个 `/delay/1` 中任一请求超过 5 秒，本次网络条件无效，应暂停验收而不是修改程序判定。服务正常时，每个 URL 只请求一次。

异步版必须与同步版得到相同分类和计数，并观察到多个延迟请求重叠、异步版总耗时低于同步版。不规定固定加速倍数。
