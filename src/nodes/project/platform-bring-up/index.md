# STM32 平台与工程

## 项目目的

从空目录建立一个可构建、烧录、调试和运行的 Embassy 固件工程，理解嵌入式 Rust 项目从编译目标到板级运行的最小链路。

本项目不要求自行实现启动代码、芯片 HAL 或完整 BSP。重点是正确选择、配置和组合现有工具与依赖，并能定位配置错误。

## 完成判据

- **核心目标**形成最小可运行结果，可用于检查当前进展；
- **标准目标**是完成本节点的判据；
- **挑战目标**用于继续深入，不影响节点完成状态。

应先得到完整的核心结果，再进入标准或挑战目标。不得以大量未完成的高级功能替代较低层的完整结果。

## 硬件与环境

导师指定下列一块开发板：

- RoboMaster Type C，MCU 为 STM32F407IGH6；
- DM-MC-Board02，MCU 为 STM32H723VGT6。

标准实现使用 Rust、Embassy 和 probe-rs。导师只提供开发板和必要器材，不提供项目脚手架、数据手册、原理图链接、引脚说明或接线教程。实现者应自行查找并核对资料。

## 核心目标

从空目录完成以下工作：

- 创建 Cargo 项目并选择正确的 Rust 编译目标；
- 配置目标芯片对应的 HAL 与 Embassy executor；
- 完成内存布局、链接参数和必要的构建配置；
- 配置 probe-rs，使固件可以烧录和调试；
- 配置系统时钟和 Embassy 时间驱动；
- 配置 panic 处理；
- 控制一个 LED 以固定周期改变状态。

不得从现成的同开发板完整工程直接复制全部配置。允许参考多个资料来源，但实现者应理解仓库中每项平台配置的作用。

## 标准目标

- 配置 RTT/defmt 日志，并输出启动信息和关键状态变化；
- 自行研究开发板上的按键和 LED 连接；
- 使用独立 Embassy task 分别处理周期事件和按键输入；
- 对按键输入进行必要的消抖处理；
- 根据按键事件改变 LED 任务的行为；
- README 说明硬件、依赖、构建、烧录、调试和运行现象。

实现应避免以忙等待长期占用执行器。共享状态或任务通信方式应符合所选类型的并发约束，不能依赖未经解释的全局可变状态。

## 挑战目标

不使用 Embassy，以传统中断模型或 RTIC 重新实现标准目标中的最小功能。挑战实现可以放在同一仓库的独立目录或分支中。

README 应基于实际实现简要比较：

- 任务或控制流组织方式；
- 时间事件与外部中断的处理方式；
- 共享资源的访问方式；
- 配置复杂度和调试体验。

比较不要求扩展为通用框架评测。

## 交付要求

使用单独的 GitHub 仓库，至少提交：

- 可构建的源代码；
- 基本可读的 Git 提交历史；
- 简短的 `README.md`，说明开发板和 MCU 型号，查明的 LED、按键和调试接口信息，构建、烧录及调试命令，关键依赖用途和运行现象。

不强制要求 CI、覆盖率、验证报告、Issue 模板或正式 code review 流程。

## 资料与依赖

实现者应自行搜索资料并判断来源。允许询问导师、与他人交流或合理使用 AI，但提交者必须理解并能解释代码。

允许合理使用第三方依赖，但依赖不得直接替代项目要训练的核心实现。提交者应能说明每个主要依赖解决了什么问题，以及为什么选择它。
