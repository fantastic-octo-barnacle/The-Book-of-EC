# 电路与电平基础

## 本章要点

电控组的工作（嵌入式软件）是相对底层的工作。在实际编写软件时，我们常常会遇到如：晶振频率，外设引脚接口的配置等与硬件息息相关的问题。因此认识基本的电路元件，了解它们的基本特性，学会根据原理图等资料获取在嵌入式软件编写过程中需要的信息，不仅能有效提升软件编写的效率，还能够加深我们对软件的理解。

在本章，你将掌握一下要点：

- 基本元器件的辨识
- 数字逻辑电路中简单的名词缩写及其含义
- 多种通信的电平协议

## 基本元器件的辨识

由于实际工程中涉及到的元器件种类繁多，难以在此一一罗列，因此仅介绍最重要的晶振。其余基本元器件需要自行了解。

### 单片机时钟与晶振

时钟信号是维持时序逻辑的重要手段。对于现代复杂计算机系统而言，维持时序逻辑的基础便是时钟信号。简单来讲，时钟信号是计算机的心跳，没有时钟，计算机就无法运行。

> 拓展内容：为什么计算机离不开时钟:[时序逻辑](#时序逻辑)

单片机的常用时钟信号有如下几种:

| 类型               | 复杂度                                                       | 精准度                           |
| ------------------ | ------------------------------------------------------------ | -------------------------------- |
| 内部 RC 振荡器     | 无需外部元件，仅靠内部元件即可完成                           | 较低                             |
| 外部振荡器（晶振） | 需要外围晶振电路，但实现相对简单                             | 较高                             |
| 外部数字时钟信号   | 由外部设备提供时钟信号，更加灵活自由，但外围电路可能更加复杂 | 与外部设备相关，可以达到极高精度 |

晶振通常指利用石英晶体谐振特性产生稳定频率的时钟源。工程中常见两类器件：

- **无源晶体（Crystal）**：本体只有晶体谐振器，需要 MCU 内部振荡器和外部负载电容共同起振。
- **有源晶振/时钟振荡器（Oscillator）**：器件内部已经包含振荡电路，通常有电源、地和时钟输出引脚。它输出的是数字时钟信号，接到 MCU 的外部时钟输入脚即可。

## 电平逻辑

外设和外设、外设和内核之间通信，需要统一的通信协议，就像人与人之间交流需要统一的语言。

数据通信协议分层架构包括物理层协议、数据链路层协议、网络层协议、传输层协议及应用层协议。
上述分层主要体现在互联网等应用中，而嵌入式通信中的数据通信协议较为简单。为便于理解，在此简化为物理层与协议层。

| 层     | 解释                                                           |
| ------ | -------------------------------------------------------------- |
| 物理层 | 决定了电路如何表示其对应码元（在二进制系统中即为如何表示0和1） |
| 协议层 | 决定了具体数据如何通过码元表示                                 |

在此，我们简要学习一下嵌入式开发中常用的物理层的电平协议。

### TTL电平

TTL电平（Transistor-Transistor Logic，晶体管-晶体管逻辑）是数字电路中最经典、最基础的电平标准之一。虽然纯TTL芯片现在已不多见，但它的电平阈值定义至今仍深刻影响着嵌入式开发（尤其是UART、GPIO电平匹配）。

| 参数              | 最小值 | 最大值 |
| ----------------- | ------ | ------ |
| 输出高电平（Voh） | 2.4V   | VCC    |
| 输出低电平（Vol） | 0V     | 0.4V   |
| 输入高电平（Vih） | 2.0V   | VCC    |
| 输入低电平（Vil） | 0V     | 0.8V   |

> TTL电平只规定了判断的界限，其最高电压是 VCC 并没有做限制。因此，5V 系统和 3.3V 系统的电压上界可能不同，在实际开发中需要注意耐压，以防烧毁芯片。

### RS232

RS-232（EIA/TIA-232-E）是历史最悠久的串行通信标准之一，主要用于近距离的点对点设备通信，比如早期电脑连接鼠标、调制解调器。

RS-232采用负逻辑，并且电压范围很宽。逻辑“1”为负电压，逻辑“0”为正电压。它用较高的电压摆幅来抵抗噪声，但代价是速度受限。

| 参数           | 逻辑"0" (SPACE) | 逻辑"1" (MARK)   |
| :------------- | :-------------- | :--------------- |
| **发送端电平** | +5V ~ +15V      | -5V ~ -15V       |
| **接收端电平** | +3V ~ +15V      | -3V ~ -15V       |
| **空闲状态**   | -               | 负电平 (逻辑"1") |

### RS485

RS-485（EIA/TIA-485-A）是目前工业控制领域应用最广泛的接口标准之一，其强大的抗干扰能力和支持多节点组网的优势，使其成为远距离通信的首选。

RS-485采用差分信号传输，逻辑状态由两根线（A和B）之间的电压差（V_AB = V_A - V_B）决定。

| 参数                  | 逻辑"1"   | 逻辑"0"   |
| :-------------------- | :-------- | :-------- |
| **发送端输出 (V_AB)** | +2V ~ +6V | -6V ~ -2V |
| **接收端识别 (V_AB)** | > +200mV  | < -200mV  |

> 是的，这里接收电压没有写错。由于其是差分信号，抗干扰能力较强，200mV 足够应对。

### CAN

CAN（Controller Area Network，控制器局域网）是一种多主从的串行通信协议，因其高可靠性和强大的错误检测机制，在汽车电子和高端工业控制中被广泛使用。

CAN总线也采用差分信号，使用CAN_H和CAN_L两根线。它定义了两种逻辑状态：显性和隐性。它具有“线与”特性，即显性位（逻辑0）可以覆盖隐性位（逻辑1）。
（以下为最常用的高速CAN（ISO 11898-2）标准）

| 参数                     | 隐性 (逻辑"1") | 显性 (逻辑"0") |
| :----------------------- | :------------- | :------------- |
| **CAN_H 电压**           | 2.5V           | 3.5V           |
| **CAN_L 电压**           | 2.5V           | 1.5V           |
| **差分电压 (V_H - V_L)** | **0V**         | **2.0V**       |

### 差分信号与单端信号

在嵌入式系统中，单端信号（Single-ended），即用一根信号线和公共地（GND）之间的电压差来表示逻辑0或1；而差分信号（Differential）则用两根物理线（如A和B）之间的电压差来表示。
两者最核心的区别在于参考基准和抗干扰能力。

| 对比维度           | **单端信号 (Single-ended)**            | **差分信号 (Differential)**                                    |
| :----------------- | :------------------------------------- | :------------------------------------------------------------- |
| **信号定义**       | 信号线电压 **相对于 GND** 的差值       | 两根线 **(A - B) 的电压差值**                                  |
| **导线数量**       | 1根信号线 + 1根地线 (GND)              | 2根信号线 (通常为双绞线)                                       |
| **参考基准**       | **地 (GND)**。若地电位波动，信号会失真 | **两线压差**。两线同时受干扰，但差值不变                       |
| **抗干扰能力**     | **弱**。对共模干扰（外部噪声）极其敏感 | **极强**。共模干扰被抵消，只认差值                             |
| **电磁辐射 (EMI)** | **大**。信号回流路径不理想，辐射较强   | **小**。两根线电流方向相反，磁场相互抵消                       |
| **传输距离**       | **短**。通常 < 几米（如TTL电平<1米）   | **长**。可达上千米（如RS-485的1200米）                         |
| **传输速率**       | **相对较低**。距离越长，速率衰减越快   | **高**。支持高速率（如USB 2.0可达480Mbps）                     |
| **电平阈值**       | 依赖 VCC 比例（如TTL判高需 >2.0V）     | 依赖 **压差正负**（如RS-485判高需 > +200mV）                   |
| **功耗**           | 相对较低（但电压摆幅通常较大）         | 相对较高（两支驱动管同时工作）                                 |
| **成本与引脚**     | **便宜**，节省GPIO引脚                 | 需要收发器芯片，且占用2个引脚                                  |
| **地线依赖**       | **高度依赖**。收发双方地电位必须接近   | **不严格依赖**。允许接收端地与发送端地有较大压差（共模范围宽） |
| **典型代表**       | **TTL电平、UART、I2C、SPI、RS-232**    | **RS-485、CAN、USB、以太网、LVDS**                             |

> 差分信号抗干扰能力主要来源于在遇到干扰时，两根信号线收到的干扰相同，最终差值不变。

## 检查题

两个模块未共地时，UART 电平为何不可靠？

> [!NOTE]发送端输出高电平（如 3.3V），这个电压是相对于发送端自己的 GND 而言的。接收端判断高低电平，是相对于接收端自己的 GND 来判断的。如果两个模块的地存在电位差（比如模块A的地比模块B的地高 2V）：
>
> - 发送端输出 3.3V（对A地）。
> - 接收端实际测到的电压 = 3.3V - 2V（压差） = 1.3V（对B地）。
> - TTL 判高阈值为 2.0V，对于接收端来说，电平为 1.3V 就会误判为低电平（逻辑0），导致通信乱码。

逻辑信号通过逻辑门时会有传播延迟（propagation delay），如果在上次逻辑信号还没完全计算完成时就开启下一轮计算，就会产生错误。
借助设置大于传播延迟的时序，我们可以保证上次计算完成后再开启下一次计算。

<ClockTimingDiagram />

同时，在复杂逻辑门系统中，可能出现多个逻辑门操作同一个状态寄存器的情况。这就会产生竞争，即不同电路读取或写入的数据会对其它电路产生影响。由于设计制造、老化程度等原因，不同逻辑门的传播延迟不同且会出现波动，这种影响可能是随机的。

假设逻辑门 AND1 需要读取寄存器 R1 的数据，将结果存在 R2 中；逻辑门 AND2 需要读取寄存器 R2 的数据，将结果存在 R1 中。
<DigitalLogicDiagram kind="competition" />
这样，我们就构建了了一个交叉耦合的闭环（类似基本的RS锁存器或SRAM存储单元）。
因为没有时钟或优先级控制，这个电路运行一次的结果，完全取决于D1和D2谁先完成“读取-计算-写入”这个完整链条。

简单来说，对于固定输入，这个逻辑电路的输出是不可预测的。

避免这种问题有很多方法，在现代计算机系统中，常用的方法便是采用时钟同步，即让不同逻辑门仅在时钟信号触发时计算，这既防止了寄存器读写竞争，还让复杂逻辑电路的设计变得简单。

#### 拓展题

一个开发板上设置了 25MHz 的晶振，但是软件开发人员把这个晶振当成了 40MHz。以下功能会产生问题的是：

A 执行计算

B 通过 UART 与外部设备通信

C 通过 SPI 作为主设备与从设备（支持频率 10MHz-80Mhz）通信
