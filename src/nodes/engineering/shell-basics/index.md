# 命令行基础

命令行不是 Linux 专属工具。Windows、Linux 和 macOS 都会用命令行启动编译器、构建系统、调试工具和版本管理工具。本节点以 Windows 上的 PowerShell 为主要操作环境，同时指出 Linux 和 macOS 上常见的差异。

学完本节点后，你应当能够：

- 将一条简单命令分成命令名、选项和位置参数；
- 在文件系统中确认当前位置，并使用绝对路径或相对路径到达目标；
- 判断一个命令名对应别名、Shell 内置功能还是外部可执行文件；
- 面对陌生工具时查找帮助、版本和实际安装位置；
- 解释当前工作目录、环境变量、`PATH` 和退出状态如何影响命令运行。

## 先分清四个对象

下列对象经常一起出现，但不是同一回事：

| 对象  | 作用                         | Windows 上的例子      |
| ----- | ---------------------------- | --------------------- |
| 终端  | 显示文字并接收键盘输入的窗口 | Windows Terminal      |
| Shell | 读取命令、解析参数并启动程序 | PowerShell、`cmd.exe` |
| 命令  | 交给 Shell 的一段文本        | `git status`          |
| 程序  | 真正执行工作的代码           | `git.exe`             |

终端可以承载不同的 Shell。同一个 Windows Terminal 标签页可能运行 PowerShell，另一个标签页可能运行 `cmd.exe` 或 WSL 中的 Bash。提示符附近出现 `PS`，通常表示当前 Shell 是 PowerShell；网上以 `C:\>` 开头的示例通常来自 `cmd.exe`，以 `$` 开头的示例通常来自 Bash 等 POSIX Shell。示例中的提示符不是命令的一部分，不要一起复制。

::: info 本节点的命令约定
本书优先使用 `ls`、`cd`、`pwd`、`mkdir`、`cp`、`mv`、`rm` 这些简短名称。在 Windows PowerShell 中，它们可能是别名或函数；在 Linux 和 macOS 中，它们通常是 Shell 内置命令或外部程序。同名不表示支持相同的参数，复制其他平台的命令前必须先确认实际运行的是什么。
:::

## 一条命令如何运行

以 `git status --short` 为例，Shell 大致完成以下工作：

1. 将输入识别为命令名 `git` 和两个参数 `status`、`--short`。
2. 按 Shell 自己的规则和 `PATH` 查找 `git` 对应的程序。
3. 启动程序，并把参数、当前工作目录和环境变量交给它。
4. 等待程序结束，接收它报告的退出状态。

这个模型能解释许多常见问题：相对路径错误通常与当前工作目录有关，“找不到命令”通常发生在查找程序时，参数报错则说明程序多半已经成功启动。

## 安全边界

- 先用 `pwd` 和 `ls` 确认位置与目标，再修改文件。
- 不执行自己无法解释的整条命令，尤其是包含删除、递归、强制或管理员权限的命令。
- 命令行删除通常不会经过图形界面的回收站。
- 本节点的修改和删除练习只能在自己刚创建、内容可以完全重建的练习目录中完成。

## 学习路线

1. [命令、参数与工具探查](./commands)：读懂一条命令，确认它实际调用什么，并查询陌生工具。
2. [目录、路径与文件操作](./filesystem)：理解目录树、工作目录和跨平台路径，安全地导航和修改练习文件。
3. [环境变量、PATH 与命令运行](./environment)：解释程序为何能被找到，以及进程会从 Shell 获得什么运行环境。

完成三个部分后，选择一个已经安装的工具，回答以下问题：

1. Shell 将哪个命令或程序与它的名字匹配？
2. 它位于哪里，为什么只写名字就能运行？
3. 它支持哪种帮助和版本查询方式？
4. 成功和失败时分别返回什么状态？
5. 换一个工作目录或打开一个新终端后，哪些条件会改变？
