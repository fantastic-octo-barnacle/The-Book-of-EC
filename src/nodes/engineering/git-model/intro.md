# Git 基础

Git 是版本管理工具。它帮助你保留项目在不同阶段的状态，并记录每次变化的目的。即使一个项目只有一名开发者，这些记录也能回答几个重要问题：项目以前是什么样、后来改了什么、哪次修改引入了问题，以及怎样回到一个确认可用的版本。

## 版本管理能做什么

假设你正在调整一段电机控制程序。第一次修改让电机正常转动，第二次修改改善了响应速度，第三次尝试却使程序无法运行。如果只反复覆盖同一份文件，很难准确恢复第二次修改后的状态，也很难说明三次修改分别做了什么。

使用 Git 管理项目后，可以有意识地保存这些阶段，并为每次保存写下简短说明。之后你可以：

- 查看项目经历过哪些修改；
- 比较两个阶段之间的差异；
- 从已知可用的版本继续工作；
- 在不破坏稳定版本的前提下尝试另一种方案；
- 与其他人交换已经整理好的修改记录。

Git 保存记录，但不会判断修改是否正确，也不会替你测试程序或决定哪些文件应该放在一起。清晰的修改范围、说明和验证仍然需要由开发者负责。

::: warning Git 不能代替备份
Git 只能恢复已经被它记录的内容。尚未保存的修改、仓库之外的文件以及只存在于损坏设备上的仓库，仍然可能丢失。重要项目还需要可靠的异地备份。
:::

## 学习路线

1. [首次 Git 配置](./setup)：让 Git 能够记录你的提交身份。
2. [创建仓库](./repositories)：用 `git init` 创建仓库，或用 `git clone` 获取已有仓库。
3. [创建 commit](./commits)：理解工作区、暂存区和本地仓库，完整保存一次修改。
4. [分支](./branches)：认识并行工作线与合并，并自行选择一套常用命令。

完成这些内容后，你应当能够在临时项目中建立仓库、创建清晰的 commit，并说明分支解决了什么问题。
