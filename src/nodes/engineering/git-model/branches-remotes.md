# 分支、stash 与远程

分支让同一个仓库同时保存多条工作线，stash 临时收起尚未提交的修改，远程仓库则用于在不同仓库之间交换提交。这三者都不会替你判断哪些修改应该保留。

## 分支是指向提交的名称

一个提交可以有后继提交，由此形成提交图。分支不是一份额外的项目副本，而是指向某个提交的名称；`HEAD` 表示当前所在分支。

<GitDiagram kind="branches" />

查看本地分支，当前分支前会显示 `*`：

```sh
git branch
```

创建新分支并切换过去：

```sh
git switch -c test
```

切换到已有分支：

```sh
git switch main
```

创建提交时，只有当前分支会移向新提交。切换分支会更新工作区文件；如果未提交修改可能被覆盖，Git 通常会拒绝切换并要求先处理修改。

## 临时收起修改

当前修改还不适合提交，但需要临时切换任务时，可以把它保存到本机的 stash：

```sh
git stash push -m "暂存编码器调试修改"
```

查看已有 stash：

```sh
git stash list
```

恢复最近一次 stash；正常恢复后，它会从列表中移除：

```sh
git stash pop
git status
```

<GitDiagram kind="stash" />

默认情况下，stash 不包含尚未被 Git 跟踪的新文件。确实需要一起保存时使用：

```sh
git stash push -u -m "暂存调试修改和新文件"
```

stash 只存在于本地，不会被推送，也不应当作为长期备份。`stash pop` 可能产生冲突；此时不要重复执行命令，先用 `git status` 确认哪些文件需要处理。

## 本地仓库与远程仓库

远程仓库是另一份 Git 仓库。`origin` 通常只是 `git clone` 自动设置的远程名称，可以用下面的命令确认其地址：

```sh
git remote -v
```

<GitDiagram kind="remote" />

开始工作前，取回远程仓库的最新提交并更新当前分支：

```sh
git pull
```

完成本地提交后，将当前分支的提交发送到远程：

```sh
git push
```

第一次推送一个只存在于本地的新分支时，需要告诉 Git 远程名称和分支名：

```sh
git push -u origin test
```

之后在该分支上可以直接使用 `git push`。

## 遇到阻塞时先停下来

| 现象                               | 可以确定的事实                 | 下一步                         |
| ---------------------------------- | ------------------------------ | ------------------------------ |
| Git 拒绝切换分支                   | 工作区修改可能被覆盖           | `git status`，决定提交或 stash |
| `git pull` 报告冲突                | Git 无法自行决定应保留哪份内容 | `git status`，按团队流程处理   |
| `git push` 被拒绝                  | 远程仓库包含本地尚未处理的提交 | 不要强制推送，先确认远程变化   |
| `git status` 显示 `unmerged paths` | 仓库正处于尚未解决的冲突中     | 停止继续同步，检查冲突文件     |

本节点只要求识别这些状态。不要在不了解后果时复制 `reset`、`rebase` 或强制推送命令来消除报错。
