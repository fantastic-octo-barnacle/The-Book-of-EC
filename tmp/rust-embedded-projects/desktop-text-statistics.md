# 公共项目：批量文本统计 CLI

## 项目目的

编写一个命令行文本统计工具，在容易运行和调试的桌面环境中熟悉 Cargo 项目结构、Rust 基本语法、错误处理、测试和依赖管理。

本项目不要求 GUI、网络、串口或嵌入式开发。异步文件处理只作为挑战目标，不应被描述为本地文件处理的性能优化。

## 输入与输出

程序接收一个或多个 UTF-8 文本文件，分别统计并汇总：

- 行数；
- 词数；
- Unicode 字符数；
- 用户指定关键词的出现次数。

词的划分规则和关键词匹配规则由学员确定，并在 README 中说明。例如，必须说明关键词是否区分大小写、统计的是独立单词还是任意子串。

遇到不存在、无法读取或不是合法 UTF-8 的文件时，程序不得无提示地崩溃。学员应选择合理的错误处理方式，并保持成功结果与错误信息可区分。

## 核心目标

- 创建并组织 Cargo 二进制项目；
- 处理单个文件；
- 使用结构体表达一份文件的统计结果；
- 将文件读取、文本统计和结果输出拆分到适当的函数或模块；
- 使用 `Result` 传播或处理可能失败的操作；
- 输出各项统计结果。

核心统计逻辑应由学员实现，不得使用能够直接完成整个文本统计任务的依赖。

## 标准目标

- 使用 `clap` 接收文件路径、关键词及必要选项；
- 支持一次处理多个文件；
- 输出每个文件的结果和合计结果；
- 单个文件处理失败时，清楚报告失败对象和原因；
- 为纯文本统计逻辑编写少量单元测试，至少覆盖正常文本和空文本；
- 在 README 中说明如何安装依赖、运行程序和执行测试。

学员应自行阅读 `clap` 文档并完成依赖添加及 feature 配置。

## 挑战目标

使用 Tokio 并发处理多个输入文件：

- 保持输出结果确定且容易阅读；
- 正确收集每个任务的成功结果或错误；
- 在 README 中简要说明同步版本与异步版本的代码结构差别；
- 明确指出异步 I/O 不保证普通本地文件读取更快。

挑战目标用于接触 `async`、`.await`、任务和并发错误处理，不要求进行性能测试。
