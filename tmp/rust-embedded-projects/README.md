# Rust 与嵌入式独立训练项目计划

## 目标

本计划面向会使用少量 C、接触过嵌入式基础知识、尚未学习 Rust 的成员。学员通过两个短项目熟悉 Rust、嵌入式 Rust 和基本开发工具，为进入复杂的 Rust STM32 正式项目做准备。

训练以学习和展示能力为主，不要求所有学员完成全部目标，也不以统一总分决定是否合格。正式项目可以根据成员实际表现分配不同难度的工作。项目结束后的面试和能力评价不属于本计划。

## 项目路径

每名学员独立完成：

1. 公共桌面项目：批量文本统计 CLI；
2. 一个嵌入式方向项目：平台与工程、CAN 电机速度闭环或裁判系统通信。

同一项目可以分配给多人独立完成。学员可以互相交流，也可以询问导师、使用 AI 或查阅网络资料，但应理解并能解释自己提交的代码。

全部任务按约 15～25 小时有效投入控制规模，不在任务书中规定分周进度。方向项目的分配方式不属于本计划。

## 统一交付要求

每个项目使用单独的 GitHub 仓库。仓库至少应包含：

- 可构建的源代码；
- 基本可读的 Git 提交历史；
- 简短的 `README.md`，说明项目用途、构建与运行方式；
- 嵌入式项目所需的硬件型号和连接说明。

不强制要求 CI、覆盖率、验证报告、Issue 模板或正式 code review 流程。

## 目标分层

- **核心目标**：形成最小完整结果。未达到标准目标的学员仍可用它展示已掌握的能力。
- **标准目标**：项目预期的完整交付范围。
- **挑战目标**：仅在适合继续深入的项目中设置，不是完成项目的必要条件。

学员应先完成较低层目标，再进入较高层目标。不得以大量未完成的高级功能替代较低层的完整结果。

## 资料与依赖

任务发放时只提供已经确定的硬件型号和必要器材，不提供协议资料、数据手册、接线教程、公共排障页或依赖推荐清单。学员应自行搜索资料、判断来源并解决问题。

允许合理使用第三方依赖，但依赖不得直接替代项目要训练的核心实现。学员应能说明每个主要依赖解决了什么问题，以及为什么选择它。

## 嵌入式项目的统一环境

- 所有嵌入式项目使用 Rust 与 Embassy；平台项目的挑战目标除外。
- 烧录和调试统一使用 probe-rs。
- 业务方向统一使用 RoboMaster Type C 开发板（STM32F407IGH6）。
- 业务方向提供经过检查的最小脚手架，只包含 Cargo 项目、编译目标、链接配置和 probe-rs 基本配置。
- 脚手架不实现时钟、日志或任何外设初始化，包括 GPIO、CAN 和 UART。
- 平台与工程方向不提供项目脚手架。
